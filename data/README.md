# Excel data

`NASA_FD001_sensor_by_cycle.xlsx` contains all 21 sensors, three operational settings, and RUL labels for the 100 training engines and 100 test engines in NASA C-MAPSS FD001.

## Workbook layout

| Tab | Contents |
| --- | --- |
| README | Measurement definitions, units, time-axis meaning, sources and interpretation notes |
| Engine index | Split, engine ID, observed cycles, endpoint RUL, failure cycle and data-sheet row ranges |
| Train sensors | All training engines, with dimensions down rows and cycles across columns |
| Test sensors | All observed test-engine measurements in the same layout |

On each data tab, columns A–E identify the engine ID, dimension, symbol, measurement description and unit. Columns F onward correspond to operating cycles 1, 2, 3, and so on. Each engine occupies 25 rows: 21 sensors, three settings and one RUL label row. Blank cells beyond an engine's final observed cycle are unavailable measurements, not zeros.

Cycles are local to each engine and do not represent shared calendar timestamps. A cycle corresponds to an engine operating cycle with a recorded cruise-condition snapshot; elapsed duration is not supplied.

## How the workbook was prepared

1. NASA's `CMAPSSData.zip` archive was downloaded using `get_nasa_turbofan.py`.
2. `train_FD001.txt`, `test_FD001.txt` and `RUL_FD001.txt` were parsed and exported as labeled CSVs. See [CSV generation details](../video/README.md#how-the-csv-files-were-generated).
3. Each engine's observations were transposed so that each sensor or setting occupies a row, with cycle numbers across columns. The original measurement values were retained.
4. Sensor symbols, descriptions and units were added from Table 2 of the original dataset's *Damage Propagation Modeling for Aircraft Engine Run-to-Failure Simulation* paper, included in NASA's archive.
5. An engine index and explanatory README tab were added. Exported data cells were checked against the source CSVs.

The workbook applies no measurement smoothing, normalization, unit conversion, interpolation, sensor removal or RUL capping. The script provided here regenerates the CSV inputs; the Excel workbook is a prepared artifact and is not regenerated by that script.

## Units and interpretation

- `deg R` is degrees Rankine, an absolute temperature scale. Celsius = Rankine × 5/9 − 273.15.
- `psia` is pounds per square inch absolute.
- `rpm` is revolutions per minute.
- `lbm/s` is pounds mass per second.
- Sensor 12's fuel-flow ratio uses `(lbm/s)/psi`.
- The original table does not specify a unit for sensor 17, bleed enthalpy. Its unit is marked `not specified`.
- Settings remain labeled 1–3 as supplied, without assigning an unverified physical-column mapping.

RUL is evaluation ground truth, not a sensor. Training RUL reaches zero at the last recorded cycle. Test RUL remains positive at the end of the observed record. Later test sensor readings are not supplied.

FD001 has one operating condition and one fault mode, high-pressure-compressor degradation. Some sensors are constant or nearly constant in this subset. The exact degradation-onset cycle is not labeled.

Source: [NASA C-MAPSS dataset](https://data.nasa.gov/dataset/cmapss-jet-engine-simulated-data). See the [repository README](../README.md#sources-and-citation) for citations and the distinction between this chosen subset and the related paper.
